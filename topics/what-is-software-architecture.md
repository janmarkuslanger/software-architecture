# What is software architecture?

Software architecture has no fixed definition. There are several perspectives on software architecture. 

- Structure oriented
- Decision oriented
- Principle oriented
- Pragmatic oriented

---

## Structure oriented

Bass, Clements and Kazman (2021) define software architecture as: 

"The software architecture of a system is the set of structures needed to reason about
the system. These structures comprise software elements, relations among them, and
properties of both."

This means that a software architecture is defined by its structures. 
A structure contains:
- elements
- relations
- properties of elements and relations

## Decision oriented

Booch (2006) states: "All architecture is design but not all design is architecture. Architecture represents the significant design decisions that shape a system, where significant is measured by cost of change."

This means that software architecture is the set of design decisions that shape a system and are costly to change.

## Principle oriented

ISO/IEC/IEEE 42010:2022 (2022) defines architecture as "fundamental concepts or properties of an entity in its environment and governing principles for the realization and evolution of this entity and its related life cycle processes".

Architecture is defined by:
- fundamental properties of an entity
- principles governing the realization and evolution of an entity

## Pragmatic oriented

Martin Fowler defined software architecture as the following: "Architecture is about the important stuff. Whatever that is".

This means software architecture is what the experienced developers think is important.
